## 第 1–2 步实验记录（已完成）

**数据来源**：[Food.com Recipes and User Interactions](https://www.kaggle.com/shuyangli94/food-com-recipes-and-user-interactions)。原始文件为 `RAW_recipes.csv` 和 `RAW_interactions.csv`，按菜谱表 `id` 与互动表 `recipe_id` 连接。相关工作可从老师目录列出的 *Generating Personalized Recipes from Historical User Preferences*（EMNLP 2019）开始。

**清洗**：检查菜谱 ID 唯一性、食材列表和发布日期，231,637 条菜谱均通过。食材名转小写、整理空白、保留完整名称，输出为 JSON 列表字符串。互动表共 1,132,367 行，排除不在 1–5 星任务范围内的 60,847 条零评分，以及 1,226 条早于菜谱发布日期的评分，保留 1,070,294 条。没有其他排除项。`row_id` 是从 1 开始的原始 CSV 数据记录编号，清洗和排序后仍保留。当前评论文本不进入模型输入。

**切分与评估**：按评分日期采用约 70/15/15 的顺序切分，同日记录留在同一时间段。验证模型只使用 2010-04-25 前的评分，最终测试模型可用 2012-09-11 前的全部评分重训。每轮用户须在截止日前有至少一条有效评分。用所有用户的有效记录求菜谱的最早评分日期，再筛选评估窗口内首评日当天、且符合用户历史条件的记录。同日评分保留，因为没有日内顺序。用户历史在该轮截止日冻结。这里的首评是数据中观察到的首个有效评分日。

**为什么保留时间顺序**：即使研究重点是食材和个人口味，预测时也只能使用当时已知的评分。逐条随机打散可能把用户未来的评分放进口味画像，或把测试菜谱的后续评分放进训练，破坏冷启动设定。时间切分也可能带来评分习惯、菜谱构成和用户群的变化。主实验保留现有划分，另按测试开始后第一年（2012-09-11 至 2013-09-10）和更晚分组，报告样本数、各模型 MAE 及个性化相对基线的改善。这项对照能观察效果是否随时间变化，单靠它无法判断变化的具体原因。

**Notebook 和汇报要点**：最终重训规模是 909,740 条评分。清洗后 815,636 条评分为 5 星，约占 76.2%，可用评分分布图说明为什么需要用户均分等强基线，并按历史长度分析 MAE。测试统计针对有历史的用户在已观察到的首评日所提交的评分。预测目标是评分星级。
